AV1-into-MP4 conformance failures on the macOS x64 nightly: not reproduced, now diagnosable

Task #99, 2026-11-22. Nightly logs of 2026-11-16 to 2026-11-21 read on every platform; the repro run on GitHub's macos-15-intel runners (Intel Core i7-8700B, 4 vCPUs) with both x64 CPU tiers and a macos-15 arm64 control, deps 1.18.0-rc3.

Outcome

  • Two of the task's four failures were already fixed. The "white frames at [1.12]" failures of 11-16 and 11-17 were not AV1's: the same jobs failed 17 to 31 other near-start cases in every container with the same message, task #58's dropped-frame fault in pipe_source (fixed 11-18). The 11-18 vspipe SIGSEGVs were task #68's teardown race (fixed in deps 1.18.0-rc1).
  • Two remain unexplained, both mp4+av1/passthrough/delayed-avi on the x64-v2 tier: a case that ran past the test's 3 minutes (11-19, rc1) and one that counted 99 pictures for 100 (11-21, rc2). Every other heavy job since #58 and #68 passed all 451 cases: two failures in about 10 macOS x64 legs, none on arm64, Windows or Linux.
  • Not reproduced, layer by layer. On each x64 tier: the two cases 60 times each, every mp4+av1 case 15 times with every core but one busy, the encoder alone 900 times from the captured Y4M, and the test's own decodes of that output 4,800 times: no failure, no hang, one video hash. 2,760 encodes and 9,600 decodes on x64 in all, and as many on the arm64 control per leg.
  • The encoder is deterministic and the decoders agree. SVT-AV1 4.2.0 (the same library version in the x64 and arm64 FFmpeg 9.0.2) wrote 100 packets and the same bytes in all 900 replays per leg, from a file, throttled one frame per 10 ms as vspipe writes, and 4 at once under load. ffprobe's and ffmpeg's decodes counted 100 pictures with libdav1d 1.5.4 (FFmpeg's choice), single-threaded, and with libaom.
  • What changed: the next failure explains itself. Every subprocess of the matrix is bounded (60–150 s), a hang is sampled (sample on macOS, gdb on Linux) and its tree killed before the test's timeout, a failing case prints its job log tail (vspipe's "Output N frames"), the output's packet count beside two decoders' frame counts, the decoder used and the job, and the nightly uploads the output, job and log (conformance-failures-<bundle>). The worker now logs its encoder arguments, so a kept job can be replayed. No retry was added, and no case is in knownFailures: that list is for cases that fail every time.
  • Also fixed (Step D): eight macOS x64 heavy legs failed on package:test's 30 s default timeout, not on a fault: --detect-native on the reserved-colour-tags fixtures (23–30 s there) and task #41's AAC test (11–30 s). They and five more tests measured at 23–31 s on that runner now state a 5-minute timeout, and the detectors run bounded at 2 minutes.

The x64 hash differs from arm64's (fb07a314… against d3cbb654…), as SIMD paths do; within an architecture it never varied. The encoder took 0.13–0.49 s a run from a file and 2.6–5.5 s throttled; nothing approached the 60 s hang limit.

Against the nightly: about 24 AV1 cases a leg and 2 failures in about 10 legs is roughly one in 120 case runs. At that rate B1 alone (960 x64 case runs) would have expected about 8. So what the nightly has and this did not is the cause or its trigger: other heavy test files running beside the matrix (the AI passes use several GB and every core for minutes; the format sweep runs on another leg) rather than CPU load alone. Not measured: memory pressure, and the 11-19/11-21 bundles (rc1, rc2), whose FFmpeg is byte-identical to rc3's on x64.

Limits

  • Hosted runners only, one run per bundle; the nightly's own conditions were not reproduced beyond what its run on this branch shows.
  • The 99-picture case's file was not kept (the nightly did not keep outputs then), so whether it held 99 packets is unknown.
  • "Load" was CPU only. Memory pressure, disk contention and other processes' GPU use were not simulated.

Scripts

  • .github/workflows/repro-output-conformance.yml: the run above (phases versions, b1, b1load, b2, b3).
  • summarize_flutter_json.py: counts a --file-reporter json run per case.
  • capture-vspipe-stdout.sh: keeps vspipe's Y4M as the encoder reads it.
  • replay_encoder.py: replays a kept job's encoder from that Y4M (B2).
  • measure_decode.py: the test's decodes, per decoder variant (B3).

The test side: VAPOURBOX_CONFORMANCE_REPEAT=N registers each case N times in one process (each its own test and verdict); VAPOURBOX_CONFORMANCE_KEEP=<dir> keeps a failing case's output, job and log, and VAPOURBOX_CONFORMANCE_KEEP_ALL=1 passing ones too.
