Task #75: the plugin format probe timed out on macOS x64

2026-11-19 · local: macOS arm64 (M-series), deps 1.18.0-rc1 (1.16.0 where marked) · CI: GitHub's macos-15-intel (i7-8700B, 4 vCPU), macos-15 (M1, 3 vCPU), windows-latest, ubuntu-24.04 · scripts in scripts/, numbers in data/

Decision

The push gate's quick plugin format probe (plugin_format_contracts_test.dart) failed on macOS x64 with "Test timed out after 15 minutes". It was slow, not hung, and one thing made it slow: havsfunc's LUTDeCrawl and LUTDeRainbow build four core.std.Lut2(a, b, function=lambda x, y: x & y) tables per call, and at 10 bits VapourSynth calls that lambda a million times per table. The probe rebuilt them in every 10-bit cell. The same cost kept the nightly full probe from ever finishing on macOS x64: its LUTDeCrawl child passed the probe's own 3600 s per-child limit.

  • The probe's children now evaluate havsfunc's pure Lut2 functions once per process into a lut= list (_LutMemoStd in Scripts/probe-plugin-formats.py). The list is bit-identical and goes through the same format checks, so the table cannot change. A push-gate test checks the identity and that havsfunc's own LUTDeCrawl still takes the memo. --no-lut-memo runs the calls as written.
  • Each call prints its time as it finishes, in every CI log, and --budget stops the probe before the test's timeout, naming the calls still running. A timeout can now tell a hang from slowness.
  • Kept in the push gate (the alternative was moving it to nightly): with the memo, macOS x64 takes 232 s where it took 442–857 s, and the push gate is the only place a deps bump meets the table before merge. The 15 minute timeout stays, now with about 4× headroom.
  • The same tables cost real previews of 10-bit sources about 8 s each on an M1: filed as task #82 (a havsfunc patch, needs a deps release). The nightly full probe also differs from the table on Linux and Windows for reasons unrelated to time: task #69 (Flow at 64x48) and task #81 (znedi3 at 720x486 on x86, VFM documentation rows).

Later (task #104, 2026-11-22): task #82's havsfunc patch 8 (deps 1.18.0-rc3) turned these eight Lut2 calls into Expr 'x y min', leaving havsfunc no Lut2 call, so the memo, --no-lut-memo and the memo test were removed from the probe; a heavy test now checks the probe's LUT calls make no Lut2 call. scripts/time_cells.py's memo option needs the probe as it was at this report (it calls memo_havsfunc_luts, now gone); the numbers here stand.

4. What the change is, and what it is not

  • Only pure functions. The memo takes a Lut2 function only when it has no closure, no defaults and names nothing (co_names empty), so its value depends on its two arguments alone; with bits, floatout, lut or lutf, or non-integer clips, the call passes through. havsfunc's x & y qualifies; the push-gate test checks a closure and a function naming max pass through.
  • The probe's measurement, not the template's call. It wraps havsfunc's module-level core inside the probe's own children only, around whatever it already is (the akarin shim on arm64, vs.core on x64). Real jobs are unchanged and still pay ~8 s per 10-bit preview (task #82).
  • Checked so it cannot rot silently. If havsfunc's lambdas change so the memo no longer applies, the push gate fails with "havsfunc.LUTDeCrawl no longer goes through the memo". Breaking the purity test on purpose made it fail with "the memo was not used" for every case.
  • Stalls are readable. --budget was exercised locally at 8 s: it listed the two running calls with their elapsed time and last cell and the 59 not started, killed the children (none left) and exited 3. A child past the 3600 s backstop is now one ERROR line naming the call and its last finished cell, where the nightly printed a TimeoutExpired traceback.
