PR CI in ten minutes

Task #84 · 2026-11-20 · .github/workflows/ci-test.yml

Result. The pull-request gate went from 28.9 min wall time (its slowest job, macOS x64; 21–31 min over the ten runs before) to 9.7 min with warm caches and 11.0 min cold. Every other job now finishes in under 7 min. Nothing that checks code a PR changes left the gate. What moved runs nightly, where a superset of each already ran.

Limits. These are single runs: one before, one cold after, one warm after. Hosted runners vary by about a minute from run to run (the cold Windows flutter job took 7.9 min, the warm one 5.0). Queue time is not counted. macOS jobs share the account's five concurrent macOS runners with any other workflow; in the warm run, a rust job queued 5 min behind other runs, though it was not on the critical path.

Other findings:

  • The Actions cache was over its limit. It held 11.4 GB against 10 GB, and each platform's Flutter SDK cache was ~2 GB, saved by every PR ref too. Main's entries were evicted, PRs missed, and each PR job then spent up to 1.6 min saving a new copy. A hit saved little: Setup Flutter took 2.3 min with a hit and 2.2–3.3 without on macOS x64, 0.8 against 1.2–1.4 on arm64, 1.6 against 1.4–2.1 on Windows, and 0.4 against 0.9 on Linux (main runs 44622077736 and 44613900935).
  • One test file at a time on macOS arm64. package:test runs half the cores concurrently, and that runner has 3. The sweep's own log line, "1 rows at once", confirms it. Most gate files wait on a worker, vspipe or ffmpeg, not the CPU.
  • The script-generation helper polled every 500 ms, for each of ~80 tests run one after another.

The Cargo cache helps less than expected: it holds dependencies only (~70 MB a job), and the worker crate and its test binaries still compile every run (105 s on macOS x64). macOS x64's flutter job is now mostly setup: 2.6 min for Setup Flutter and 1.8 for code generation, with the Intel runner slow at both. The next lever, if it creeps over 10 min, is to split that job's tests into a pure-Dart job and a shell-out job (plan §2E, E1).

4. Decisions and what wasn't tested

  • The smoke rows run on Linux only. A broken template block (a Python error, a wrong argument) fails on every platform. Platform-specific runtime faults (#72's SIGILL, #66's SIGSEGV) were deps-bundle faults that nightly's full sweep reaches. Trade-off: such a fault is now found the morning after a merge, not before it.
  • This reverses task #75's "kept in the push gate". Its reason, the cost, went away with #75's memo. A deps change still runs the probe before merging.
  • Nightly is red on every leg (run 44562921675, 2026-11-19). A check that moves there only helps if someone reads it.
  • Not yet seen on CI: the conditional probe step's true path (a PR's own run, whose merge diff contains deps-sensitive.sh, will take it), and nightly's new whisper step. Locally, deps-sensitive.sh gives the expected answer for the last 20 merges, a missing base and a deps_run_id.
