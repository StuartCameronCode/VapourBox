DeDot, Bifrost, LUTDeCrawl and LUTDeRainbow quantised every sample of a deeper source

2026-11-15 · task #37 (found in task #34) · deps 1.16.0 · measured on an Apple Silicon Mac (macOS arm64 bundle). The fix is integer arithmetic in zimg and Expr, so it doesn't depend on the platform; the nightly heavy run covers the other platforms.

Outcome: fixed. Four filters in the Chroma Fixes pass have a depth limit: DeDot and Bifrost take 8-bit only, and havsfunc's LUTDeCrawl and LUTDeRainbow refuse anything above 10-bit. Each guard converted the whole clip down, ran the filter, then up-converted the whole result to the source format, with error-diffusion dither. On a real capture with genuine low bits that left 78% of samples different from the source at 10-bit, 94% at 12-bit and 99.6% at 16-bit. Most of those were in samples, and whole planes, the filter never touches: Bifrost and LUTDeRainbow never change luma, and LUTDeCrawl never changes chroma. A smooth luma ramp came back banded.

Each guard now applies only the filter's change at full depth, through one helper in both templates (one template since task #42):

def _low_depth_change(clip, bits, filt):
    low = core.resize.Bilinear(clip, format=...bits...)       # as before: rounding, no dither
    up = lambda c: core.resize.Point(c, format=clip.format.id)
    return _expr([clip, up(filt(low)), up(low)], "x y + z -")

It is task #34's DeScratch fix, unchanged. Every sample the filter left alone is bit-exact. A changed sample is the filter's change plus the source's own residual, within half a low-depth level of the low-depth result. The filters still see exactly the picture they saw before, so what they remove is unchanged. 8-bit sources (DeDot, Bifrost) and 8–10-bit sources (LUTDeCrawl, LUTDeRainbow) don't go through the helper and run exactly as before.

1. The pre-check: do the filters leave untouched samples exact?

#34's formula is only right if a filter leaves the samples it doesn't change bit-exact at its working depth. If a filter rounded or nudged every sample, "only its change" would be the whole frame. So each filter was run on its working-depth copy first, and the set of samples the fix changes at full depth was compared with the set the filter changed at low depth. They are identical in every plane, format and range below (the set column). That agrees with the code: both havsfunc functions are MaskedMerge(input, fixed, mask) plus the input's other planes, and LUTDeCrawl's scene-change path returns the input.

Fixtures

A deep file converted from an 8-bit master has zero low bits, so every old guard was already bit-exact on it. The fixtures here carry synthetic low bits instead:

  • capture: 12 frames of Tests/TestResources/interlaced_test.avi (real 720x576 PAL interlaced VHS), promoted to 16-bit with a smooth ripple of ±1.5 10-bit levels on luma and chroma (#34's fixture).
  • artefacts: the capture's first frame held still, with dot crawl and rainbow injected at 8-bit: a luma checker of ±4 levels and a chroma pattern of ±8 alternating per column, both flipping every frame. The same ripple is added. On the moving capture the filters find little to do; here each works on most of a plane.
  • ramp: a horizontal luma ramp from 64 to 80 in 8-bit levels with flat chroma, for banding.

Each is converted to the format under test and flagged field-based TFF, as the templates mark an interlaced source. The LUT filters' runs clear _FieldBased, because havsfunc treats them as frame-based. Each filter runs at the templates' defaults.

Trap (from #34): R78's _Range follows H.273, so 0 is limited and 1 is full, the opposite of the old _ColorRange. Full range scales by (2n−1)/(2m−1), not a power of two, so the low-bits column is limited range only.

The artefacts fixture's other formats and ranges (4:2:0, 12/16-bit, full range) are in the script output and show the same pattern: the set always matches, nothing below the working depth is lost. "Max from low" is 0.38 rather than 0.50 for the 8-bit filters at 12/16-bit because there the residual is just the ripple, ±1.5 10-bit levels (0.375 of an 8-bit level), which never reaches half a level.

The LUT filters change far more of the picture than DeScratch. On the moving capture LUTDeCrawl changes 36% of luma and LUTDeRainbow 40% of chroma: they average across frames wherever the neighbours agree. So the fix protects the other ~60% of those planes, and every plane they don't touch, rather than ~99% of the frame. In the changed samples it keeps the source's 12/16-bit residual on top of the 10-bit change, within half a 10-bit level of the 10-bit result. Bifrost and DeDot change a few percent on the capture, like DeScratch.

Decisions

  • One helper, _low_depth_change(clip, bits, filt), next to _expr in both templates. Each block wraps its plugin call in a local function with the call text unchanged, and calls the helper only above the plugin's limit. New depth guards should use it.
  • #34's choices carry over: zimg both ways rather than a shift in the expression (it is right in full range too), and the delta rather than a mask (it keeps the source's low bits in changed samples).
  • The down-conversion is unchanged: zimg rounding, no dither. DeDot's Bicubic became Bilinear; at equal size and subsampling no resampling happens, so its input is the same.
  • Frame properties now come from the source. The one property lost is LUTDeCrawl's _SceneChangePrev/Next, which it left on scene-change frames, only at ≤10-bit, and nothing downstream reads.
  • DeScratch keeps #34's inline version: its 8-bit body is several statements (4:2:2 carrier, chroma modes), and moving it onto the helper is a tidy-up, not a fix.
  • Not porting LUTDeCrawl/LUTDeRainbow to run natively above 10-bit: havsfunc's std.Lut2 masks are what cap them (two 10-bit inputs is the table's limit), and the 10-bit decision is ample for an analog artefact. The fix already keeps every sample they don't change.

Limits of these measurements

  • The low bits are synthetic: a ripple and a ramp, not a real 10/12-bit capture. Bit-exactness and low-bit preservation are exact integer statements that don't depend on what the low bits hold.
  • The injected crawl and rainbow are a regular pattern, not real composite artefacts. They are there to make each filter work on most of a plane; the removal comparison says the fix removes the same as the filter does at its own depth, not how good the filters are.
  • Measured on macOS arm64 only. The arithmetic is integer zimg and Expr, with no CPU-dispatched code of our own.

For every plane: untouched samples bit-exact, the changed set equal to the low-depth run's, every sample within half a low-depth level of its result, the low bits kept everywhere, and preview = encode for each filter. On the old templates all six precision cases fail ("samples the N-bit run left alone must be bit-exact"). DeDot, Bifrost and LUTDeRainbow also joined the pass matrix, so they now run at 12/14/16-bit and in the 8 vs 10-bit parity check (0.17–0.19 mean abs diff).
