DeScratch Blur Radius on short frames

2026-11-15 · task #35 · deps 1.16.0 · measured on an Apple Silicon Mac (macOS arm64 bundle). The limit is integer arithmetic in the plugin's constructor, so it is the same on every platform; the nightly heavy run covers the others.

Outcome: built. The panel offers Blur Radius 1–200, but the plugin refuses blurlen > height // 2 - 1 ("Descratch: blurlen is too large for the clip height!"), so a job on any frame under 402 lines failed with values the panel offers. Both templates now pass min(blurlen, c.height // 2 - 1), computed inside _descratch from the clip each call is given. At the limit the plugin already blurs to 2 rows, its strongest; the clamped call is bit-identical to choosing the limit.

1. The limit

The plugin alone on BlankClips 720 wide, every blurlen 0–200 (sweep.py), in the four forms the template can call it with. The largest accepted value is height // 2 - 1 (equivalently, height // (1 + blurlen) ≥ 2) in every form; the plugin's own cap is 200. It is the luma height that counts, also on 4:2:0, and _FieldBased makes no difference. No other error appeared below the limit.

Correction to the task. The task, the task #29 report and its ENGINEERING_NOTES entry said values "above 119 on 480 lines, above 59 on 240" were refused. Both are off by a factor of two: 119 is the limit for 240 lines, and a 480-line source accepts every value up to 200.

2. The clamp gives the limit's picture

A dark two-pixel column on a two-tone grey frame, field-flagged 4:2:2, mindif=3 (sweep.py, second table): at 240, 288 and 360 lines the clamped call (asked for 200) is byte-identical to the call at the limit, and the limit's picture differs from the default 15's, so the comparison is not trivially true. The heavy test repeats this through the whole worker on a real scratched capture (288 lines, 4:2:0): blurlen 200 and 143 encode byte-identically, and 143 differs from 15.

Decisions

  • Clamp in the script, not in Rust. The worker knows the source height, not the height at the pass; the script reads it from the clip each call gets, so an earlier pass that changed it would still be handled.
  • No panel warning. With the clamp an out-of-range value is harmless (it means "as much blur as the frame allows"), and the app does not know the height at the pass. The parameter's description says so instead.
  • The range stays 1–200. Lowering it would take values away from 1080-line sources, where they work.

Not tested

  • Other platforms' bundles by hand (same plugin source; the nightly heavy run covers them).
  • Whether such long blurs remove scratch better on real film: no scratched-film fixture exists (as in task #29).
