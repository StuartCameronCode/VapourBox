9-bit sources: Dehalo's YAHR failed, and CTMF waited in five more places

2026-11-15 · task #31 · deps 1.16.0 · measured on an Apple Silicon Mac (macOS arm64 bundle); Windows and Linux are covered by the nightly heavy run, not measured here. Follows 14-bit sources (task #23), which found the YAHR failure.

Outcome: built. CTMF (ctmf.CTMF, r5) accepts 8, 10, 12, 14 and 16-bit integer and 32-bit float, not 9-bit. havsfunc calls it through MinBlur(r>=2) and directly, so a 9-bit source, which was piped natively (yuv4xxp9le), failed Dehalo's YAHR. The same failure was waiting in HQDeringmod at HD, FineDehalo with contrasharpening, MCTemporalDenoise's MinBlur(2) prefilter, ContraSharpening at radius 2, and SMDegrain's contrasharp at HD.

pixel_format::decode_pixel_format now decodes 9-bit as 10-bit, the same mechanism as 14 → 16. The conversion loses nothing and costs nothing (both depths use 2 bytes a sample). The Noise Reduction CTMF block's own 9-bit guard is gone, since no 9-bit clip can reach it. The one visible effect: with Output Colour Format original, a 9-bit source comes out 10-bit. Only FFV1 and FFVHuff would have stored 9 bits (+1.2% FFV1 size on the fixture).

1. A real job, before and after

FFV1 fixtures made losslessly from one degraded interlaced MPEG-2 master (testsrc2 plus seeded noise, TFF, 352x288, 2 s). Each was run with vapourbox-worker --config to FFV1 at Colour Format original, with three pipelines: the default (QTGMC, TFF), Dehalo YAHR alone, and Noise Reduction CTMF (radius 3) alone. Each failure was CTMF: only constant format 8, 10, 12, 14, 16 bit integer and 32 bit float input supported. "Same picture": the 9-bit CTMF output before, read as 10-bit, has the same MD5 as the output after (yuv422p9le): a median commutes with an exact shift. The default pipeline's 9-bit output differs, since QTGMC now works at 10 bits: 51.4 dB (4:2:0) and 52.7 dB (4:2:2) average PSNR between before and after, which is rounding.

3. The 9 → 10 decode is lossless

The same yuv444p9le frame, decoded by the bundled ffmpeg as yuv444p9le and as yuv444p10le (shift_check_9.py):

rangesamplesexact x<<1y>>1 == xmax distance from x·1023/511
limited3041283041283041281.00
full3041282541823041281.00

In both ranges every 9-bit value survives in the top 9 bits of the 10-bit sample. In full range ffmpeg scales toward x·1023/511 rather than shifting, so the low bit is sometimes set; nothing is lost either way.

4. Output at Colour Format original

  • libx264, libx265 and libsvtav1 already encode a 9-bit input as 10-bit (yuv420p9le → yuv420p10le), so their output is unchanged in format.
  • FFV1 and FFVHuff stored 9 bits and now store 10: +1.2% FFV1 size on the 2 s fixture (2 560 276 → 2 590 647 bytes). ProRes and v210 have fixed formats and are unaffected.
  • The app still calls the source 9-bit (pixelFormatBitDepth), so "your N-bit source will be output as 8-bit" warnings stay correct.

5. Decisions

  • Built: 9-bit decodes as 10-bit in pixel_format::native_name (depths 8/10/12/16). NATIVE_FORMATS and pipe_source.py drop the three p9le entries; test_no_native_format_is_9_or_14_bit fails if either depth comes back, in the list or from native_name.
  • Removed: the Noise Reduction CTMF block's 9-bit guard (lift to 10, filter, restore 9). Nothing can reach it, and it was the only per-call depth guard of this class left in the templates. The CTMF picture on a 9-bit source is unchanged (section 1).
  • Rejected: guards around YAHR and the other calls. Six calls in both templates, two of them only at HD, and the next havsfunc path through MinBlur would need another.

6. Tests

  • Rust: pixel_format unit tests (every 9-bit layout → 10, no native format or native_name result at 9 or 14), test_242_9_bit_source_pipes_as_10 (script and encoder_input_pix_fmt, with YAHR and CTMF on, and no 9-bit guard left), and test_128 no longer expects the guard.
  • Heavy (integration_high_bit_depth_filters_test.dart): "preview runs on deeper formats" gains a yuv422p9le row (every pass, 55 tests, all pass). A new group compares 9-bit with 10-bit previews: passthrough 0.105, YAHR 0.105, CTMF 0.113 levels mean abs diff (fixtures alone 0.105; the two fixtures are separate conversions of the master), and encodes the default pipeline to FFV1 from yuv420p9le (output yuv420p10le, 50 frames).

7. Not tested

  • Windows and Linux bundles directly; their CTMF is the same r5, and the nightly heavy run covers them.
  • Real-world 9-bit files. FFV1 and H.264 High 4:4:4 Predictive can be 9-bit; the fix keys on the decoded format, so the codec does not matter.
