Deps scripts: a \ continuation that ended on a comment

2026-11-27 · task #111 (found by task #103) · measured on GitHub Actions build-deps-* runs of this branch and of main, dispatched together · every number below comes from scripts/ run against the run IDs given, and the raw output is in data/.

Outcome: the scripts now say what they build, and the builds are unchanged. In both download-deps-linux.sh and download-deps-macos.sh, the environment written above VapourSynth's meson setup never reached it, because the \ continuation ran onto a comment line. On Linux that meant meson always used the system gcc, apt's Cython and the zimg subproject. That is now the written-down build, and the dead parts are gone. On macOS the two "prefixes" became script-wide assignments that the later plugin builds depend on. They are now written as assignments, with the same effect. A/B against main, built together: Linux's libvapoursynth.so.4 is byte-identical on x64 and arm64. Linux loses only the standalone libzimg.so*, which nothing loaded, and the Cython wrappers. Every meson line of every macOS build is identical. A push-gate lint now fails on any continuation that runs into a comment or blank line.

The two lines

Linux, since 0c805a7b:

PATH="$PYTHON_DIR/bin:$PATH" \
PKG_CONFIG_PATH="$BUILD_DIR/pkgconfig:$BUILD_PREFIX/lib/pkgconfig" \
LD_LIBRARY_PATH="$PYTHON_DIR/lib:$BUILD_PREFIX/lib:${LD_LIBRARY_PATH:-}" \
env ${VS_CC:+CC="$VS_CC"} ${VS_CXX:+CXX="$VS_CXX"} \
# Run meson with the EMBEDDED python, …        <- the command ends here: a bare `env`
"$PYTHON_BIN" -m mesonbuild.mesonmain setup build …   <- runs with none of the above

The bare env printed the environment into every build log (PKG_CONFIG_PATH=…, LD_LIBRARY_PATH=…), and that was the only visible sign.

macOS, since 3094c648 (2026-08-07), which inserted the Cython-wrapper paragraph between the "prefixes" and the command:

PATH="$PYTHON_DIR/bin:$BREW_PREFIX/opt/cython/bin:$PATH" \
PKG_CONFIG_PATH="$BUILD_DIR/pkgconfig:$BREW_PREFIX/lib/pkgconfig" \
# meson looks for a "cython3" program …        <- the two become plain assignments

PATH was already exported, so from that point every later command saw the embedded Python's bin first. PKG_CONFIG_PATH became an unexported shell variable: meson setup doesn't see it, but every later PKG_CONFIG_PATH="…:${PKG_CONFIG_PATH:-}" prefix expands it.

So joining the macOS command would have changed every later plugin build (Homebrew's meson and python3, and one fewer PKG_CONFIG_PATH entry). Making the Linux variables apply would have changed the compiler, made zimg a dynamic library (needing an RPATH, and leaving task #103's wrap pin dead), and swapped Cython for pip's unpinned latest. Neither fixes anything a user sees, so the decision (option B) was to keep the builds and fix the scripts.

The change

  • Linux: meson setup is one command with no environment. Before it, the script fails unless gcc -dumpversion ≥ 13 and cython3 is Cython 3, which is what R78 needs. Removed: the clang selection, the Cython wrappers (they were shipped in python/bin, with the build machine's path in their exec line), the python*.pc and zimg.pc files (no meson run read them), the standalone zimg build, and $BUILD_PREFIX/lib from ninja's LD_LIBRARY_PATH. A stale libzimg.so* is deleted from an existing deps/ on a re-run.
  • macOS: the wrapper loop moves above the two lines, which become deliberate assignments with a comment saying they last for the rest of the script. PKG_CONFIG_PATH stays unexported. They stay inside the VapourSynth if; a local re-run that skips VapourSynth builds the plugins with Homebrew's meson and python3, as it did before.
  • Guards: shell_line_continuation_test.dart scans every shell script under Scripts/, .github/scripts/ and packaging/ and every workflow file. Heredoc bodies are skipped. On the old scripts it reports exactly download-deps-linux.sh:403 and download-deps-macos.sh:545 and nothing else. zimg_pin_test.dart now fails on a standalone zimg clone or copy, on an offered zimg.pc, and on a PKG_CONFIG_PATH, CC or CXX on VapourSynth's setup.

Limits

  • The bundle diff shows the shipped binaries are unchanged. It doesn't run them; the CI runs above do.
  • The lint is a text scan. It sees a continuation running into a comment or blank line, outside heredocs. It doesn't parse shell, so a \ at the end of a line inside a quoted multi-line string would count as a continuation. None exists today.
  • The macOS Cython wrappers still carry the build machine's path, as the Linux ones did. They are used during the build only, so this is a cosmetic defect, left as it is.

Scripts

  • scripts/meson_lines.sh <run> <job name>: the compiler, Cython, zimg, python3 and meson lines of a build-deps job log. data/*-main.txt and data/*-branch.txt are its output, with build directory numbers normalised.
  • scripts/compare_bundles.sh <main.zip> <branch.zip>: the file, NEEDED/RUNPATH, libzimg and libvapoursynth.so.4 comparison. data/bundle-diff-*.txt is its output.
  • The repo scan is the test itself, app/test/shell_line_continuation_test.dart.
