QTGMC Draft SIGSEGV on Linux x64 (96x66 4:2:0)

Task #66, 2026-11-17. Measured on GitHub's ubuntu-24.04 runners (Intel Xeon 6975P-C with AVX-512, AMD EPYC 9V74 / 9V45 / 7763), deps 1.16.0 linux-x64 (VapourSynth R78, MVTools master built from source, havsfunc r31). Every number comes from .github/workflows/repro-native-crash.yml; the run IDs are in data/.

Outcome

  • The crash did not reproduce. The push gate's 96x66 4:2:0 12-bit row of deinterlace/qtgmc[preset=Draft] crashed vspipe once (CI run 44028906054, attempt 1). The re-run of the same row on the same CPU class passed. In 4,200 replays of the exact captured scripts and input (plain and single-threaded, up to 8 at once on 4 cores) and 3 runs under valgrind, the row neither crashed nor showed a memory error (table 1).
  • The likeliest cause is task #68, found meanwhile by task #65: vspipe R78 counts a frame done before writing it, so for a one-frame preview that is ready at once, main can free the script while the callback still writes. Task #65 measured it at 2 in 1,200 Bwdif previews without a trigger, a rate this many replays could easily miss. Fixed upstream in R80. This report could not confirm it: no crash, so no backtrace.
  • Every Linux CI crash now names itself. The Linux jobs of ci-test.yml and nightly.yml keep core dumps (.github/scripts/enable-core-dumps.sh: piped to a capped handler, gdb installed), and the on-failure step print-crash-reports.py prints a gdb backtrace. Before, Linux printed nothing after "signal 11". The harness banner now also prints the CPU model. Proven on the FlowInter crash below (section 3).
  • The push gate tolerates this one crash text on this row until #68 lands: a flaky knownFailures entry, limited to the Draft variant, 4:2:0 at 96x66, and the text vspipe exited with signal 11 (SIGSEGV). Any other failure of that row still fails the gate.
  • Found on the way, filed separately:
    • Task #70: on x86 Linux, QTGMC reads uninitialised memory when the chroma width is odd and the depth is above 8 bits. That includes a real 722x480 4:2:0 12-bit source. In Draft it is the last chroma column, traced to mv.Degrain1's output frame. In Slower it reaches the motion search, and the whole picture depends on it (section 2). It is not the crash: the crash row has an even chroma width and is valgrind-clean.
    • Task #69: mv.FlowFPS / mv.FlowInter corrupt the heap at 64x48 on Linux x64, in every format, in 3 runs of 3 (section 3).

How it was reproduced

The worker runs vspipe-bin directly, not the bundle's vspipe wrapper (the first capture attempt wrapped the wrong file and caught nothing). .github/scripts/replay-vspipe.sh install moves vspipe-bin aside and puts a script in its place. For every run whose script matches a pattern (here Preset="Draft"), the script saves the script, arguments, environment and stdin (the decoded frames). One run of the push-gate test captures the variant's six rows. replay-vspipe.sh run then runs them straight through vspipe, with no Flutter or worker in the loop, about 27 runs a second on a 4-core runner.

scripts/bare.vpy runs one call (QTGMC at a preset, or one MVTools setup) on a synthetic moving pattern at any size and format, with no padding and no worker. scripts/locate.py finds which output samples are uninitialised. Valgrind reports a write() of uninitialised bytes once per call stack, so it runs one memcheck process per region, first 8-row bands per plane, then 8-column bands of each band that complained.

A third tool, a buffer-pool probe, was tried and dropped: it rendered a call after filling VapourSynth's frame pool with two different values and compared the results. It found nothing, even on x86 at sizes where valgrind finds uninitialised output. It does not show what it was meant to, so it is not in scripts/.

2. Uninitialised chroma at an odd chroma width (task #70)

So it needs an odd chroma width and more than 8 bits, and QTGMC's own arrangement of supers and vectors. The first 8-bit run failed with a script error from a bug in bare.vpy's fill (a sample over 255). The 8-bit rows above are from the fixed script. 10-bit was not run.

Which samples (locate.py, data data/locate.txt):

  • Draft 98x96 12-bit: the last chroma column, x = 48 of 49, of U and V, in every row. Luma is clean. Reading MVDegrains.cpp, Degrain copies the uncovered right and bottom strips at nWidth[plane] = nWidth[0] >> xSubUV, which is 49 here. Why that column stays unwritten is open; task #70 has the next steps.
  • Slower 98x96 12-bit: every sample of every plane. The bad column feeds the motion search (valgrind: conditional jumps in pobExpandingSearch, doPobSearchMVs, pobRefine), so the whole result depends on it.

What this means for output: on x86 Linux, a QTGMC deinterlace of a 10–16-bit source whose width is 2 mod 4 (4:2:0 or 4:2:2) takes values from whatever was in a recycled buffer. It is not a crash, but preview and encode, or two runs, need not agree. Not checked on arm64 or Windows (no valgrind there).

3. FlowFPS / FlowInter at 64x48 (task #69)

Scripts/probe-plugin-formats.py --calls mv.FlowFPS,mv.FlowInter, three times on one runner (data data/flow_probe_64x48.txt): all 12 reachable 64x48 cells of each call crashed in every run (SIGSEGV, sometimes SIGABRT). Every other size ran. The committed probe table says these cells are ok. The new crash report printed the core's backtrace (data/gdb_flowinter_64x48.txt):

Program terminated with signal SIGSEGV, Segmentation fault.
#0  _int_free_merge_chunk (... size=844424930132000) at ./malloc/malloc.c:4678
#1  _int_free (...) at ./malloc/malloc.c:4646
#2  __GI___libc_free (mem=...) at ./malloc/malloc.c:3398
#3  mvflowinterGetFrame(int, int, void*, void**, VSFrameContext*, VSCore*, VSAPI const*) () from .../plugins/libmvtools.so
#4  VSNode::getFrameInternal(int, int, VSFrameContext*) () from .../libvapoursynth.so.4

free() finding a corrupt chunk size inside mvflowinterGetFrame means the heap was overwritten before it. That is a buffer overflow in the Flow code at a tiny frame, deterministic on x86. It also shows the Linux crash report works: the plugin and the function, from a runner nobody can log into.
